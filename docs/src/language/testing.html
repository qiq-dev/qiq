Testing

A test is a top-level function whose name starts with test_ and which takes a Test from std/testing. qiq test finds the tests, runs each one, and reports the ones that fail, like Go's go test.

```qiq import Test from "std/testing"; import argv from "std/os"; function slug(string title): string { return str_replace(" ", "-", strtolower(trim(title))); } print(slug(argv()[1])); function test_slug(Test t): void { t->equal(slug("Hello World"), "hello-world"); t->equal(slug(" Trim Me "), "trim-me"); } ``` ```sh qiq run slug.qiq "My First Post" # runs the program: the test is just an unused function qiq test slug.qiq # runs the test instead of the program ```

Tests can sit in the program they test, as here, which suits a script of a single file. A program of several files can keep them in separate files, such as money_test.qiq next to money.qiq, which import what they test. qiq build and qiq run ignore test functions, and the optimizer drops them, so they add nothing to an executable.

Running tests

```sh qiq test # every .qiq file with tests, below the current directory qiq test slug.qiq money_test.qiq qiq test -run slug # only tests whose names contain "slug" qiq test -v # list every test, not just the ones that fail ```
  • Each file is compiled as a program of its own, without its top-level code: main calls the file's tests, in the order they're written.
  • A test runs in its file's directory, so it can read files kept next to it.
  • A failed assertion stops its test, and the next test runs. So does an exception that escapes a test, which fails it.
  • qiq test exits with status 1 if any test failed or a file didn't compile, for use in scripts and CI.

A failure says where and why. Had test_slug also checked t->equal(slug("Two Spaces"), "two-spaces"), which this slug gets wrong, qiq test would report:

```text --- FAIL: test_slug (0.00s) slug.qiq:13: expected "two-spaces", found "two--spaces" 0 passed, 1 failed FAIL slug.qiq 0.74s ```

Assertions

Each assertion knows the file and line it's called from, which a failure reports. The Test class reference has every method's signature.

MethodFails when
t->equal(actual, expected)The values differ, as == compares them: arrays and maps by their contents, objects by identity
t->notEqual(actual, unexpected)The values are equal
t->isTrue(condition, message), t->isFalse(condition, message)The condition isn't true (or false); the message is optional
t->near(actual, expected, tolerance)Two doubles differ by more than the tolerance (10-9 by default), for results of arithmetic such as 0.1 + 0.2
t->throws(fn() => ..., "ExceptionClass")Calling the function doesn't throw an exception of that class, by name (any exception for "Exception", the default)
t->fail(message)Always

equal and notEqual take any two values of the same type, and comparing values of different types, such as t->equal(count, "3"), is a compile error. A failure shows both values as print writes them inside an array, with strings quoted, so "3" and 3 look different, and with doubles in full: expected 0.3, found 0.30000000000000004.

Two more methods don't fail: t->log(message) notes something, shown if the test fails (or with -v), and t->skip(reason) stops the test, which counts as skipped. t->name() is the test's function name.

Test classes

Tests can also be public methods named test_... in a class, which suits tests that share a setup. Each test runs on a new instance of its class, so tests can't leak state into each other through its properties: its constructor and setUp(), if it has one, run first, and tearDown() runs after the test, even when the test fails. Both can come from a parent class.

```qiq import Test from "std/testing"; import Database from "std/sql"; class AccountTest { private Database db; function setUp(): void { this->db = Database::open("sqlite::memory:"); this->db->execute("CREATE TABLE accounts (id INTEGER PRIMARY KEY, balance INTEGER)"); } function tearDown(): void { this->db->close(); } public function test_deposit(Test t): void { this->db->execute("INSERT INTO accounts (balance) VALUES (?)", 100); t->equal(this->db->queryOne("SELECT balance FROM accounts")->getInt("balance"), 100); } public function test_starts_empty(Test t): void { t->equal(len(this->db->query("SELECT * FROM accounts")), 0); } } ```

A test method is reported as AccountTest::test_deposit, and -run matches that name, so qiq test -run AccountTest runs one class. Test functions and test classes can share a file; their tests run in the order they're written. The class needs a constructor that can be called without arguments; set things up in setUp instead. Abstract classes aren't run, so a base class can hold the setup that several test classes share.

Table-driven tests

Many cases of one check fit a loop over an array:

```qiq import Test from "std/testing"; class Case { function __construct(public string input, public string want) {} } function test_slug_cases(Test t): void { Case[] cases = [new Case("A B", "a-b"), new Case("x", "x"), new Case("", "")]; foreach (cases as c) { t->log(f"input \"{c->input}\""); t->equal(slug(c->input), c->want); } } ```
