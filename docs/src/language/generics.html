Generics

A generic class or function has type parameters, written in angle brackets after its name, that stand for types given where it's used. One Stack<T> serves as a stack of ints, of strings, or of any class, and the compiler checks each use with the real types.

```qiq class Stack { private T[] items = []; function push(T item): void { array_push(this->items, item); } function pop(): T { return array_pop(this->items); } function size(): int { return len(this->items); } } Stack names = new Stack(); names->push("Ada"); names->push("Lin"); print(names->pop(), names->size(), names); ``` ```output Lin 1 Stack ```

Generic classes

  • Declare type parameters after the class name: class Pair<A, B>. Inside the class they're types like any other, for properties, parameters, return types, variables, and arrays and maps: T[], map[string, T].
  • Use the class with type arguments: Stack<int>, Pair<string, User>, Stack<Stack<int>>. Any type can be one, including int and ?int.
  • A class can mention itself and other generic classes with its parameters, as a linked list's Node<T> next does.
  • Generic classes can implement interfaces, and their objects work everywhere objects do: as interface values, in arrays and maps, with json_encode and json_decode, and in print, where they show their type arguments.

Inferring type arguments

new can leave the type arguments out when the compiler can tell them: from the type the object is used as, or else from the constructor's arguments.

```qiq class Pair { public A first; public B second; function __construct(A first, B second) { this->first = first; this->second = second; } function swap(): Pair { return new Pair(this->second, this->first); } } Pair pair = new Pair(1, "one"); print(pair->swap()->first, pair->swap()); ``` ```output one Pair ```

Generic functions

A function's type parameters come after its name. A call usually leaves the type arguments out: they come from the arguments' types, and when those don't decide (as for a function that only returns a T[]), from the type the result is used as. A call can also give them.

```qiq function firstOr(T[] values, T fallback): T { return len(values) > 0 ? values[0] : fallback; } function transform(T[] values, function(T): U change): U[] { U[] result = []; foreach (values as value) { array_push(result, change(value)); } return result; } print(firstOr([3, 4], 0), firstOr([], "none")); print(transform([1, 2, 3], fn(n) => n * 10)); print(transform(["a", "bb"], fn(string s) => len(s))); ``` ```output 3 none [10, 20, 30] [1, 2] ```

An anonymous function argument, like fn(n) => n * 10 above, takes its parameter types from the other arguments, and its return type decides U. An anonymous function whose parameter types are all written needs nothing from the others. Arguments that need a type to have one ([], {}, null) take it from the other arguments too, or from the type the result is used as: in int[][] groups = fold(values, fn(acc, x) => acc, []), the declaration says what the [] and acc are.

When an argument gives a different type for a parameter than an earlier one did, the call is an error: T is int from an earlier argument, but string here. A callback of the wrong type shows both types (expects a callback of type function(int): U for 'change', found function(string): string), and so does a value of the wrong kind (expects T[] for 'values', found int).

Giving type arguments

A call can give its type arguments between the name and the (, as new can. That's needed when neither the arguments nor the use of the result say what a type parameter is, as for a function with no arguments whose result is passed straight on. It works the same way for functions, methods, and static methods.

```qiq function emptyOf(): T[] { return []; } class Repeat { static function times(T value, int count): T[] { T[] result = []; while (len(result) < count) { array_push(result, value); } return result; } } print(len(emptyOf())); print(Repeat::times('x', 3)); ``` ```output 0 ['x', 'x', 'x'] ```

Given type arguments decide their parameters before the arguments are looked at, so [], null and anonymous functions take their types from them. An argument of another type is an error: firstOr<int>([], "none") gives T is int from the type arguments, but string here. A call gives all of the type arguments or none of them, and a function or method that isn't generic takes none.

A < after a name is read as type arguments only when what follows can only be a type, closed by >, and followed by (. So a < b is still a comparison.

Generic methods

A method can have type parameters of its own, alongside its class's. Like a generic function's, they come from the arguments at each call. Static methods can be generic too.

```qiq class Box { public T value; function __construct(T value) { this->value = value; } function convert(function(T): U change): Box { return new Box(change(this->value)); } } Box number = new Box(21); Box label = number->convert(fn(n) => f"#{n * 2}"); print(label->value, label); ``` ```output #42 Box ```

Inheritance

Generic classes take part in inheritance like any other: one can be abstract, extend a class, generic or not (class Stack<T> extends Collection<T>), and be extended, by another generic class or by an ordinary class for particular types (class History extends Stack<string>). parent:: calls the parent's methods, and static members belong to each class made from the generic one: Collection<string> and Collection<int> each have their own.

```qiq abstract class Repository { protected map[int, T] items = {}; function save(int id, T item): void { this->items[id] = item; } function count(): int { return len(this->items); } abstract function name(): string; } class UserRepository extends Repository { function name(): string { return "users"; } } Repository users = new UserRepository(); users->save(1, "Ada"); print(users->name(), users->count()); ``` ```output users 1 ```

Generic interfaces

An interface can have type parameters too: Repository<User> declares methods that take and return users. A class implements it for particular types (class Money implements Comparable<Money>), or a generic class for its own (class MemoryRepository<T> implements Repository<T>), and its methods must match the interface's with those types filled in.

```qiq interface Repository { function find(int id): T; function save(T item): void; } class MemoryRepository implements Repository { private map[int, T] items = {}; function find(int id): T { return this->items[id]; } function save(T item): void { this->items[len(this->items) + 1] = item; } } Repository names = new MemoryRepository(); names->save("Ada"); print(names->find(1), names); ``` ```output Ada MemoryRepository ```

Here new MemoryRepository() takes its type argument from the interface it's used as.

Bounds

Without a bound, generic code can only store, pass, return, and compare a T, since it could be any type. A bound, written T: Interface (or a class), says what T must be: generic code can then call that type's methods, and each use is checked to give a type that is one.

```qiq interface HasLength { function length(): int; } class Word implements HasLength { public string text; function __construct(string text) { this->text = text; } function length(): int { return len(this->text); } } function longest(T[] items): T { T best = items[0]; foreach (items as item) { if (item->length() > best->length()) { best = item; } } return best; } print(longest([new Word("hi"), new Word("hello")])->text); ``` ```output hello ```

Calling longest with objects that aren't a HasLength is the error longest's type parameter T must be a HasLength, but Plain isn't one.

A bound can be a generic interface that mentions the parameter itself, so generic code can compare a T with another T:

```qiq interface Comparable { function compareTo(T other): int; } class Money implements Comparable { public int cents; function __construct(int cents) { this->cents = cents; } function compareTo(Money other): int { return this->cents - other->cents; } } function largest>(T[] items): T { T best = items[0]; foreach (items as item) { if (item->compareTo(best) > 0) { best = item; } } return best; } print(largest([new Money(5), new Money(12), new Money(7)])->cents); ``` ```output 12 ```

Map keys

A map's keys can be ints, doubles, bools, strings, or chars, so map[K, V] needs K to be one of those. The bound K: key says so: generic code can use a K as a map key, compare it with == and <, and turn it into a string with to_string or an f-string.

```qiq function groupBy(T[] items, function(T): K keyOf): map[K, T[]] { map[K, T[]] groups = {}; foreach (items as item) { K k = keyOf(item); if (!map_key_exists(k, groups)) { groups[k] = []; } array_push(groups[k], item); } return groups; } print(groupBy(["tea", "jam", "cake"], fn(w) => len(w))); print(groupBy([1, 2, 3, 4], fn(n) => n % 2 == 0)); ``` ```output {3 => ["tea", "jam"], 4 => ["cake"]} {false => [1, 3], true => [2, 4]} ```

Without the bound, map[K, V] is the error a K can't be a map key: K could be a type keys can't have; declare it as K: key, and passing another type for a K: key is the error groupBy's type parameter K must be a map key type (int, double, bool, string, or char), but int[] isn't one. Generic code with a K: key is checked with K as an int and as a string, since it must work for every key type, so a mistake such as len(k) names one of them: function 'f<int>': len expects a string, array, or map, found int, with a note saying why.

How it works

The compiler makes a copy of a generic class or function for each set of type arguments the program uses, with the types filled in, so generic code runs exactly as fast as code written for those types: a Stack<int> stores plain ints. Generic code is also checked once on its own, even if nothing uses it, with each T standing for its bound, or for a type with no methods; a mistake shows up there rather than at some later use.

Type parameters and null

A T without a bound could be a type that can't be null, such as int, so generic code can't treat it as able to be null: comparing it with null, setting it to null, and giving it a ?? fallback are errors, such as a T can't be compared with null: T could be a type that can't be null, such as int. A T with a bound is always an object, so it can be null; when any object type will do, the bound T: object says so, and allows null. ?? on a map or array element of type T (items[key] ?? fallback) works either way, since it tests for a missing key or index.

Rules

  • A generic class's static property can be read with its type arguments (Box<int>::count), but only assigned inside the class, with self::.
  • Interface and abstract methods can't have type parameters of their own yet, and generic methods can't be overridden. A constructor's type parameters are its class's.
  • ?T isn't allowed, since T may already be a type that can be null. instanceof can't test for a generic class.
  • A generic function can't be used as a function value.
  • Type arguments are exact: a Stack<Dog> isn't a Stack<Animal>, even when a Dog is an Animal.
