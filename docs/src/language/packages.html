Packages

qiq packages work like Go modules. A module is a directory of qiq files with a qiq.mod file at its root, which names the module and lists the modules it uses. A module's name is its import path, and for a published module it's also where the code lives, such as github.com/ada/web, so there's no central registry: publishing a library means pushing it, with a version tag, to a repository.

qiq mod init github.com/you/myapp     # make this directory a module
qiq get github.com/ada/web            # add a module, at its latest version
qiq run main.qiq                      # downloads anything missing, then builds

Creating a module

Run qiq mod init with the module's path in the project's root directory:

```sh qiq mod init github.com/you/myapp ```

This writes qiq.mod:

```text module github.com/you/myapp qiq 0.1 ```

The qiq line is the oldest qiq version the module works with; an older compiler refuses to build it. A module path is made of letters, digits, and . _ ~ -, separated by /. A module you'll publish should be named after its repository (github.com/you/myapp); a program nobody imports can be called anything, such as myapp.

The compiler finds qiq.mod in the entry file's directory or the nearest directory above it, so qiq run cmd/tool.qiq and cd cmd && qiq run tool.qiq both work. Without a qiq.mod, a program works as before, with relative imports only.

Imports within a module

A file can import another file of its own module by the module path plus the file's path from the module root. Unlike a relative path, this stays the same wherever the importing file is:

```qiq // cmd/tool.qiq, in module github.com/you/myapp import Page from "github.com/you/myapp/views/page"; // views/page.qiq import shout from "../views/util"; // relative paths still work ```

Adding modules: qiq get

qiq get downloads a module and records it in qiq.mod and qiq.sum:

```sh qiq get github.com/ada/web # the latest release qiq get github.com/ada/web@v1.4.2 # a specific version qiq get github.com/ada/web@latest # the same as no version qiq get -u github.com/ada/web # update one module to its latest release qiq get -u # update every module this one requires directly qiq get # download everything qiq.mod requires (after a clone) ```
  • A module's versions are its repository's git tags named like v1.4.2. Publishing a version means pushing a tag: git tag v1.4.2 && git push origin v1.4.2. The latest version is the newest release; prereleases such as v2.0.0-beta.1 are used only when asked for by name, or when a module has nothing else.
  • The module path is the repository's address: github.com/ada/web is cloned from https://github.com/ada/web with git, which must be installed to download modules (building needs nothing but qiq once they're downloaded).
  • Modules that a module needs are added too, marked // indirect in qiq.mod. qiq prints what it added or changed and why: qiq: added github.com/lin/slug v0.3.0 (required by github.com/ada/web v1.4.2).
  • qiq get rewrites qiq.mod in a standard layout, so comments in it aren't kept.

Requiring other modules

qiq.mod lists the modules a module imports with require, each with the minimum version it needs. qiq get maintains these lines, but they can be edited by hand too. Versions are semantic versions with a v: v1.4.2, v2.0.0-beta.1.

```text module github.com/you/myapp qiq 0.1 require github.com/ada/web v1.4.2 require ( github.com/lin/slug v0.3.0 // several in a block ) ```

Then import a required module's files by their path inside it:

```qiq import Mux from "github.com/ada/web/mux"; // mux.qiq in the module import slugify from "github.com/lin/slug"; // the module's main file, slug.qiq ```

The module path on its own means the module's main file, named after the last part of the path: "github.com/lin/slug" loads slug.qiq from the module's root, which suits small single-file libraries.

  • Imports are resolved in this order: a path in the importing file's own module, then a path in a required module (the longest matching module path), and otherwise a path relative to the importing file. Paths starting with ./ or ../ are always relative.
  • A path that looks like a module (its first part contains a dot, as in github.com/...) but matches no required module and no local file is an error that says to add a require.
  • Required modules can require modules too. Every module in a program comes from the main module's qiq.mod, at one version each: the newest version that any of the modules asks for. This is Go's minimal version selection: the build uses exactly the versions written down, and nothing changes until you run qiq get. Asking for an older version than another module needs keeps the newer one, with a message saying which module needs it.
  • A module's code is compiled into the program like any other qiq file. Fetching and building a module never runs any of its code, unlike package managers with install scripts.

Using a local copy: replace

replace uses a directory instead of the downloaded module, for developing a library alongside an application, or for a fork:

```text require github.com/ada/web v1.4.2 replace github.com/ada/web => ../web ```

The directory is relative to qiq.mod (or absolute). If it has a qiq.mod, its module line must match the required path. Only the main module's replace lines take effect.

Keeping things private

Every top-level function, class, and interface can be imported, including by other modules. Two ways keep a module's internals to itself, so you can change them without breaking its users:

  • Declare it private: private function clean(string path): string { ... }. Files in the same module can still import it.
  • Put files in a directory named internal: files under github.com/ada/web/internal/ can only be imported from within github.com/ada/web.

Checksums: qiq.sum

qiq.sum records a hash of the files of each module version the build uses:

```text github.com/ada/web v1.4.2 h1:P3wFdtmxYaYtcdfH3SbQES8F8YYC0N+K/JcCEpwe3NI= github.com/lin/slug v0.3.0 h1:8p5eL4L9oP+ADnHU0tNwjYAaeQd1SP+xZ2HTihh3k24= ```

Commit it with qiq.mod. Every later download of those versions, on any machine, must match: if someone moves a tag to different code, or the download is tampered with, the build stops with checksum mismatch for github.com/lin/slug v0.3.0 and deletes what it downloaded. A required module without a qiq.sum line is an error that says which qiq get to run. The hash is computed like Go's go.sum h1: hashes: a SHA-256 over the SHA-256 of each file and its path.

Downloads during builds

qiq run and qiq build download any version that qiq.mod requires but the cache doesn't have, checking it against qiq.sum, so after cloning a project, qiq run main.qiq just works. They never change qiq.mod or choose versions; only qiq get and qiq mod tidy do.

Removing modules: qiq mod tidy

qiq mod tidy reads the imports in the module's files and makes qiq.mod require exactly the modules they use, plus what those need (marked // indirect). It removes the rest from qiq.mod and qiq.sum, and reports imports that no required module provides. It skips hidden directories and directories with their own qiq.mod.

Where modules are kept

Downloaded modules are shared by all projects, in ~/.cache/qiq/mod/<module path>@<version> (in $XDG_CACHE_HOME/qiq/mod if that's set, or in $QIQ_MODCACHE). Each version is downloaded once, without its .git directory or symbolic links, and its files are made read-only so they aren't edited by accident; to change a module, use a local copy with replace. Deleting the cache is safe: modules are downloaded again when needed.

Private repositories

qiq downloads with your git, so git's settings and credentials apply. To fetch private GitHub repositories over SSH:

```sh git config --global url."git@github.com:".insteadOf "https://github.com/" ```

Git never asks for a password during qiq get; it fails with git's message instead.

Standard library names

Standard library modules are imported from std/ paths, such as import Router from "std/http/server";, so their names don't get in a package's way: a package can declare its own Router, Response, or File, and a program that needs both imports one under another name with as. Only the prelude, the string functions, the general functions, and the exception classes, is reserved everywhere. Paths starting with std/ always mean the standard library.
