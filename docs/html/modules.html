    Modules

    A program can span several files. Import functions, classes, and interfaces from another file by name with import Name, Other from "path";.

    // views/template.qiq
interface Template {
    function getHtml(string template): string;
}
    // views/page.qiq
import Template from "template";

class Page implements Template {
    private string title;

    function __construct(string title) {
        this->title = title;
    }

    function getHtml(string template): string {
        return str_replace("{title}", this->title, template);
    }
}
    // main.qiq
import Page from "views/page";

Page page = new Page("Home");
print(page->getHtml("<h1>{title}</h1>"));

    Compile or run the entry file as usual; the compiler loads its imports, and theirs, and produces one executable:

    qiq run main.qiq
    <h1>Home</h1>

    Import paths

    • Paths are relative to the importing file, so "../shared/util" works too. In a module, a path can also start with the module's path ("example.com/app/views/page") or a required module's path ("github.com/ada/web/mux").
    • .qiq is added when the path has no extension.
    • Each file is loaded once, however many files import it.
    • Import cycles are an error that lists the cycle, for example import cycle: a.qiq -> b.qiq -> a.qiq.

    What can be imported

    • Every top-level function, class, and interface in a file can be imported. Imported names are used unqualified, exactly as if they were declared in the importing file.
    • Names a file imports are not re-exported: import them from the file that declares them.
    • A name is visible only in files that declare or import it, so two files can each declare their own helper function or Item class without clashing.
    • Classes can extend imported classes and implement imported interfaces, and interface calls dispatch across files.
    • The everyday parts of the standard library (strings, the general functions, and the exception classes) are available everywhere without an import, and their names can't be redeclared. The rest is imported from std/ paths, such as import File from "std/file";; see Standard library.

    Importing under another name

    Imported names are used unqualified, so two files that export the same name clash. Import one of them under another name with as:

    import Mux as WebMux from "github.com/ada/web/mux";
import Mux from "views/mux";

WebMux api = new WebMux();

    The new name works everywhere the original would: new, extends, implements, catch, and type declarations. Objects still print, and error messages still show, the class's own name. Importing a name twice without as is an error that suggests it.

    Private declarations

    Mark a top-level function, class, or interface private to keep it out of reach of other packages: it can still be imported by files in its own module (the directory tree of its qiq.mod), but not from another module.

    // github.com/ada/web/mux.qiq
private function clean(string path): string {
    return trim(path, "/");
}

class Mux {
    // ... uses clean() ...
}

    Another module's import clean from "github.com/ada/web/mux"; is the error 'clean' is private to module github.com/ada/web. A program without a qiq.mod is a single module, so there private doesn't restrict anything.

    File structure

    • Imports must come before all other declarations.
    • Only the entry file may contain top-level statements. Imported files contain only imports and declarations, so importing a file never runs code.
    • Errors name the file they occur in, for example views/page.qiq:12:5: ....
    • import and from are contextual keywords, so they can still be used as variable names.
