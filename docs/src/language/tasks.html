Tasks and concurrency

A task is a function running concurrently with the rest of the program. Tasks are lightweight threads, called fibers, on the program's one thread: a task runs until it waits (for another task, a channel, or sleep), and then another runs. Only one runs at a time, so tasks need no locks and can share variables and objects safely; while waiting, they cost a little memory and no time. They come from std/async:

```qiq import spawn, Task from "std/async"; import usleep from "std/time"; function slowSquare(int n, int milliseconds): int { usleep(milliseconds * 1000); print("finished", n); return n * n; } Task a = spawn(fn() => slowSquare(3, 30)); Task b = spawn(fn() => slowSquare(4, 10)); print("both started"); print(a->await() + b->await()); ``` ```output both started finished 4 finished 3 25 ```

The two calls slept at the same time, so the program took about 30 milliseconds rather than 40.

Starting tasks

  • spawn(f) starts f, a function that returns a value, as a task, and returns a Task<T>. task->await() waits for it to end and returns its result.
  • launch(f) starts a function that returns nothing, and returns a Job, whose join() waits for it.
  • A started task first runs when the code that started it waits (for example in await), so starting several and then awaiting them runs them together.
  • yield_now() lets the other ready tasks run, for a task that computes for a long time without waiting.

Exceptions

An exception a task throws ends the task, and await (or join) throws it in the code waiting for it, so it can be caught there:

```qiq import spawn, Task from "std/async"; Task failing = spawn(function(): int { throw new RuntimeException("the service is down"); }); try { failing->await(); } catch (RuntimeException e) { print("caught:", e->getMessage()); } ``` ```output caught: the service is down ```

A task that throws when nothing awaits it isn't lost: when the program ends, its exception is reported as an uncaught exception, and the program exits with status 1.

Channels

A Channel<T> passes values from tasks that send them to tasks that receive them, in order. new Channel<T>(capacity) holds up to capacity values, so send waits only when it's full; with no capacity, each send waits until a task receives the value. close() says no more are coming, and foreach receives values until the channel is closed and empty:

```qiq import launch, Channel, Job from "std/async"; Channel jobs = new Channel(10); Job worker = launch(function(): void { foreach (jobs as job) { print("working on", job); } }); jobs->send("resize photo"); jobs->send("send email"); jobs->close(); worker->join(); ``` ```output working on resize photo working on send email ```

Cancelling, and time limits

task->cancel() stops a task: what it's waiting for, or the next thing it waits for, throws CancelledException in it, which ends the task unless it catches that. A task that hasn't started yet doesn't run at all. await then throws CancelledException too. A cancelled task isn't reported when the program ends, since it was stopped on purpose.

with_timeout(seconds, f) runs f as a task and returns its result, cancelling it if it takes longer than the limit; then it throws TimeoutException. Both exceptions come from std/async:

```qiq import with_timeout, TimeoutException from "std/async"; import usleep from "std/time"; function slowAnswer(): int { usleep(2000000); return 42; } try { print(with_timeout(0.1, fn() => slowAnswer())); } catch (TimeoutException e) { print(e->getMessage()); } print(with_timeout(1.0, fn() => 7)); ``` ```output timed out after 0.1 seconds 7 ```

Anything that lets other tasks run can be cancelled: await, channels, sleep, network requests and database queries, and commands, which are stopped. Work running on a helper thread (an SQLite query, reading a file) finishes first, and the task hears of the cancellation straight after.

Waiting on several channels

receive_any(channels) waits until one of several channels has a value, and returns which one and the value, as a tuple:

```qiq import launch, receive_any, Channel from "std/async"; import usleep from "std/time"; Channel emails = new Channel(1); Channel texts = new Channel(1); launch(function(): void { usleep(20000); texts->send("running late"); }); (int which, string message) = receive_any([emails, texts]); print(which, message); ``` ```output 1 running late ```

The end of the program

The program ends when its main code and every task have ended: tasks still running when the main code finishes are waited for. exit() ends the program at once, tasks and all.

Deadlocks

When every task is waiting for something only another task could do, such as receiving from a channel nothing will send on, none can go on. Rather than hang, the program throws a RuntimeException in a waiting task: deadlock: every task is waiting (for a task, a channel, or the end of the program), so none can go on.

What waits, and what doesn't

A task lets others run whenever it waits for something outside the program:

  • network I/O: the HTTP client, sockets (including TLS), looking up host names, and PostgreSQL and MySQL queries;
  • SQLite queries, and reading and writing whole files (file_get_contents, file_put_contents, file_get_bytes, file_put_bytes), which run on a helper thread meanwhile;
  • running commands with exec and shell, while the command runs;
  • sleep and usleep from std/time;
  • and, within the program, await, join, and a channel's send and receive.

So three HTTP requests that each take a second, run as tasks, take about a second together:

```qiq import spawn, Task from "std/async"; import http_get from "std/net/http"; Task[] requests = []; foreach (["https://example.com/", "https://example.org/", "https://example.net/"] as url) { array_push(requests, spawn(fn() => http_get(url)->status)); } foreach (requests as request) { print(request->await()); } ```

Timeouts work as before: a request that times out throws in its own task while the others go on. Database work from several tasks takes turns: one query runs at a time, each with its own values and results, and a task waiting its turn lets the others run. A few things still make every task wait while they run: reading and writing a file a line or a chunk at a time with File, the other file functions (such as scandir and copy), and code that computes without waiting (which can call yield_now to let others run).

Using several processor cores

Tasks are concurrent, not parallel: they share one processor core, which suits waiting but not computing. For work that needs several cores, parallel(f) runs f in a worker process, on another core, and returns a Task whose await gives the result; parallel_map shares an array's items among one worker per core:

```qiq import parallel, parallel_map, Task from "std/async"; function countPrimes(int from, int to): int { int count = 0; foreach (range(from, to) as n) { bool prime = n > 1; int d = 2; while (prime && d * d <= n) { prime = n % d != 0; d++; } if (prime) { count++; } } return count; } Task low = parallel(fn() => countPrimes(1, 50000)); Task high = parallel(fn() => countPrimes(50001, 100000)); print(low->await() + high->await()); print(parallel_map([10, 100, 1000], fn(int n) => countPrimes(1, n))); ``` ```output 9592 [4, 25, 168] ```
  • A worker starts as a copy of the program at the moment parallel is called: the function sees the values it captures as they are then, and what it changes stays in the worker.
  • Its result is copied back as JSON, so it can be any type json_encode writes (numbers, strings, arrays, maps, tuples, enums, and objects, whose public properties are copied); a function value is a compile error. An exception it throws becomes a WorkerException, whose message starts with the original's class.
  • It's a task like any other: await lets other tasks run, and cancelling it (or a with_timeout around it) stops the worker's process.
  • A worker shouldn't use the parent's open database connections or sockets, which it shares the underlying connection of; open its own.

The HTTP server uses several cores on its own, with a worker process each, and can serve several requests per worker as tasks with http_serve's concurrency.
