Types

Every value in qiq has a type known at compile time. There are no implicit conversions between types: mixing them is a compile error, and the conversion functions convert explicitly.

int

An int is a signed 64-bit integer. Arithmetic wraps on overflow, so 9223372036854775807 + 1 is -9223372036854775808. A negative literal is written with unary minus; -9223372036854775808, the smallest int, can be written directly.

double

A double literal has a decimal point, an exponent, or both: 2.5, 1e5, 2.5E-3. A literal with an exponent is always a double, so int n = 1e5; is an error. Double arithmetic follows IEEE 754: 1.0 / 0.0 is inf.

bool

Conditions in if, while, &&, ||, and ! must be bool; qiq has no "truthy" values, so if (count) is an error. print(true) prints true.

byte

A byte holds 0 to 255 and is meant for binary data, such as the contents of file_get_bytes. An int literal becomes a byte wherever a byte is expected, and out-of-range literals are compile errors. Bytes can be compared (as unsigned values) and printed, but not used in arithmetic: convert with to_int first.

```qiq byte[] header = [137, 80, 78, 71]; if (header[0] == 137) { print("PNG signature"); } print(to_int(header[1]) + 1); ``` ```output PNG signature 81 ```

string and char

A string is UTF-8 text and a char is one Unicode character. See Strings and chars.

null

null is what a void function call evaluates to (see Functions). It can be stored wherever a string, char, array, map, or object is expected, meaning "no value", but not in an int, double, bool, or byte: for those, use their nullable forms, such as ?int. Strings, arrays, maps, and objects that haven't been given a value, such as the elements of new string[3], are null too. Using a null value throws RuntimeException; test for it with == null (see Operators and Variables).

Nullable scalars: ?int, ?double, ?bool, ?byte

Writing ? before int, double, bool, or byte makes a type that holds that scalar or null: an optional field, a lookup that may find nothing, or a number from JSON or a database that may be missing. A plain value converts to its nullable type automatically, so an int can be assigned or passed wherever an ?int is expected.

```qiq ?int age = null; ?double score = 9.5; print(age, score, age == null, score == 9.5); age = 41; int next = (age ?? 0) + 1; print(next); ``` ```output null 9.5 true true 42 ```

A nullable value can be compared with == and != (with null, with its scalar, or with another value of the same nullable type), printed, put in strings and f-strings (as null when it's null), and stored in arrays, maps, and properties. json_encode writes it as its value or null, and json_decode accepts either. Everything else, such as arithmetic and <, needs the scalar: give a fallback with ??, or check for null first.

Checking for null

After a check, the compiler knows the variable isn't null, and treats it as its scalar where the check holds:

  • inside if (x != null) { ... }, and in the else of if (x == null);
  • after if (x == null) { return; } (or throw, break, or continue), for the rest of the block;
  • on the right of x != null && ... and x == null || ..., and in the branches of x != null ? ... : ....
```qiq function describe(?int age): string { if (age == null) { return "unknown"; } return to_string(age + 1); } ?int[] readings = [3, null, 7]; int total = 0; foreach (readings as reading) { if (reading != null && reading > 2) { total += reading; } } print(describe(null), describe(41), total); ``` ```output unknown 42 10 ```

This works for local variables and parameters that the checked code doesn't assign to, and that no anonymous function captures (either could make them null again). A property checked the same way, such as this->age or user->age, is its scalar there too; since something else could set a property to null in the meantime, each read of it there checks, and throws RuntimeException if that happened. Using a nullable value unchecked is a compile error that says how to fix it: '+' requires two ints or two doubles, or strings and chars to concatenate; found ?int and int; a ?int may be null: check it with != null first (then it's int there), or give a fallback with ??.

Strings, chars, arrays, maps, and objects can already be null, so ?string and ?User are errors: write string and User. Map keys can't be nullable.

Arrays, maps, objects, and functions

Arrays, maps, objects, and function values are references: assigning one to another variable, or passing it to a function, shares the same underlying value rather than copying it.

```qiq int[] first = [1, 2]; int[] second = first; second[0] = 99; print(first); ``` ```output [99, 2] ```

Tuples

A tuple type such as (int, string) is a fixed number of values, each with its own type, as a function returns several values: return (count, name);. Tuples are references too, but can't be changed.

Type names in errors

Error messages write types as they appear in source: cannot assign map[string, bool] to map[string, int] variable 'm'.
